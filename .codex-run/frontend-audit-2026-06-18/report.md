# NoteGen 前端体验审计

日期：2026-06-18  
范围：公开首页、公开示例笔记、桌面三栏工作台、移动端工作台与章节抽屉、服务离线状态。  
视口：1280x720、390x844。后端未启动，因此登录后笔记库、真实生成任务和问答结果未做端到端验证。

## 结论

当前重构方向是对的：NotebookLM 风格的内容优先、三栏工作台、统一 token 和真实时间戳联动已经形成产品骨架。主要问题不是视觉风格落后，而是响应式信息顺序、语言状态、浮层可达性和公开体验入口尚未收口。

建议先完成 P0，再做卡片和细节美化。否则视觉投入会被移动端首屏、内容遮挡和中英混排抵消。

## 已确认的优点

- 三栏心智清晰：来源/章节、笔记正文、视频/工具的职责明确。
- 浅色和深色 token 基本统一，卡片边界、圆角和强调色克制。
- 桌面端独立滚动、章节高亮、时间戳跳转和导出入口已经构成完整学习工作台。
- 移动端章节抽屉视觉清楚，章节标题和时间点易扫读。
- 加载骨架、离线提示和错误态均已存在，不是空白页。
- TypeScript 和生产构建通过。

## P0：先解决

### 1. 移动端首屏顺序压住了核心价值

移动端先展示播放器、横向章节、4 个工具按钮，再展示笔记标题和摘要。390x844 下首屏看不到笔记核心内容，用户会把产品理解成播放器而不是“视频转结构化笔记”。见 `03-note-workspace-mobile.png`。

对应代码：`web/components/NoteWorkspace.tsx:396` 将正文设为 `order-2`，`web/components/NoteWorkspace.tsx:421` 将视频工具设为 `order-1`。

建议：移动端改成“标题/摘要 -> 视频紧凑卡 -> 知识点”，导出、分享、书签收进一个“更多工具”菜单；播放器可保持 sticky，但默认高度不应超过首屏约 35%。

### 2. 底部问答条遮挡正文

问答条在桌面知识点列表和移动端标题区域上方形成遮挡，当前截图中已覆盖卡片或关键词。见 `03-note-workspace-mobile.png`、`08-keypoints-desktop.png`。

对应代码：`web/components/NoteWorkspace.tsx:412` 使用 `sticky bottom-3`，但内容区没有与浮条高度匹配的底部安全空间。

建议：桌面端为滚动区增加稳定的底部 padding；移动端将游客登录提示改为正文内联卡片，登录后的输入条再使用固定/粘性模式，并处理 safe-area。

### 3. 语言开关没有控制整个页面

持久化语言为 EN 时，首页仍是中文；示例笔记中 UI/章节摘要变成英文，但标题、关键词和部分内容仍是中文。用户看到的是中英混排，不是双语切换。见 `02-note-workspace-desktop.png`。

对应代码：`web/app/page.tsx` 未读取 `useLang`，首页文案全部硬编码；`web/components/LangContext.tsx:47` 在缺少目标语言字段时回退原字段，页面没有显式提示“部分内容无翻译”。移动端又在 `web/components/NavBar.tsx:61` 隐藏语言开关，用户无法现场修正。

建议：先定义切换语义：是“界面语言”还是“笔记内容语言”。最好拆为两个设置；若暂时保留一个开关，则首页、导航、工具、章节和内容都必须一致切换，缺译时显示清晰状态而不是静默混排。

### 4. 移动章节抽屉不是完整的模态交互

抽屉打开后视觉正常，但焦点仍停留在抽屉背后的打开按钮；主内容未 `inert`/`aria-hidden`，正文滚动也未锁定。键盘和读屏用户仍可进入背景内容。

对应代码：`web/components/NoteWorkspace.tsx:555-588` 只设置了 `role="dialog"` 和 `aria-modal`，没有初始焦点、焦点循环、关闭后焦点恢复和背景隔离。

建议：抽屉打开时将焦点移到关闭按钮或标题，限制 Tab 在抽屉内，Escape 关闭，关闭后返回触发按钮，并锁定背景滚动。

### 5. “试用 NoteGen”实际要求先登录

首页主 CTA 文案是“试用”，但直接去登录；公开示例笔记虽然存在，却没有首页入口。用户在验证产品价值之前先承担注册成本。

对应代码：`web/app/page.tsx:45`、`web/app/page.tsx:70`。同时公开导航却暴露内部 `/mm-ablation` 实验入口（`web/components/NavBar.tsx:51`），产品优先级倒置。

建议：首页主 CTA 直接打开一篇最佳公开示例，次 CTA 才是“登录并创建笔记”；从公共导航移除 ablation，放到开发/研究入口。

## P1：结构打磨

### 6. 1280 宽度下中栏偏窄，知识点卡片过密

当前固定为 `260px + 中栏 + 400px`，1280 宽度时正文只有约 550px，却在 `xl` 断点显示 3 列知识点卡。卡片可读性和摘要信息量明显下降，右栏相对过重。见 `07-note-workspace-light-zh.png`、`08-keypoints-desktop.png`。

建议：右栏收至 340-360px，左栏收至 232-240px；知识点在 1440px 以上再进入 3 列，1280 保持 2 列。

### 7. 知识点卡存在隐藏但可聚焦的操作

卡片本身是 `role="button"`，内部又有跳转、查看大图和书签按钮。操作层仅通过 hover 改透明度，键盘焦点或触屏不会稳定展示，但隐藏按钮仍参与焦点和点击。

对应代码：`web/components/KeyPointsGrid.tsx:44-60`、`web/components/KeyPointsGrid.tsx:79-105`。

建议：卡片用普通 `article`，标题区域提供“查看详情”主操作；图片上的操作在 `hover`、`focus-within` 和触屏下都可见，避免一个交互容器嵌套多个独立交互。

### 8. 离线恢复页缺少退路

离线态只提供“重试”，没有返回公开首页、查看公开示例或诊断提示。服务长时间不可用时用户被困在空页面。见 `06-notebooks-offline.png`。

对应代码：`web/components/RequireAuth.tsx:34-45`。

建议：增加“返回首页”和“查看公开示例”；开发环境可显示后端地址，生产环境保持简短。

### 9. 小字号与浅色三级文字有对比风险

代码中有 64 处 10-11px 文本。浅色 `--fg-tertiary: #80868b` 对 `#f8fafd` 的对比度约 3.52:1，低于普通小文本常用的 4.5:1 目标。

对应代码：`web/app/globals.css:16`，例如 `web/components/LangToggle.tsx:31`、`web/components/ChapterRail.tsx:40`。

建议：正文辅助信息最低 12px；浅色三级文字加深到约 `#6f7479`，不可只依赖低对比颜色表示状态。

## P2：工程质量与性能

- `npm run lint` 当前失败：5 个错误、6 个警告。错误集中在 `ChatPanel.tsx`、`NoteWorkspace.tsx`、`lib/progress.ts`；应作为合并门禁修复。
- `NoteWorkspace` 每个播放器 `timeupdate` 都更新顶层 `currentTime`（`web/components/NoteWorkspace.tsx:428`），会带动整个工作台重渲染。可将高频播放状态下沉到播放器/章节指示器，或按帧节流并 memo 化正文。
- 知识点图片使用原生 `<img>`，没有 `loading="lazy"`、尺寸约束或 Next Image；当前 lint 已提示 5 处图片优化警告。长笔记会一次渲染大量关键帧。
- 公开示例加载先请求后端再回退静态文件（`web/lib/notes.ts:71-81`）。本次后端离线时示例笔记出现数秒骨架；应增加短超时、并行回退或明确静态 demo 路径。
- Landing 动效处理了 reduced motion，但工作台和弹层中的 Framer Motion 尚未统一采用同一策略。

## 推荐实施顺序

第一轮（高收益，建议一个迭代）：移动端重新排序、修复问答条遮挡、统一语言语义、完善抽屉焦点、首页增加公开示例 CTA、移除公共 ablation。

第二轮：调整三栏宽度与卡片断点、重构知识点交互语义、增强离线恢复、修复小字号对比度、清零 lint、优化高频重渲染和关键帧加载。
