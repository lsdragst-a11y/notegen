# NoteGen Logo 与认证体验设计

日期：2026-06-18

## 1. 目标与范围

本设计建立 NoteGen 的品牌入口体验，覆盖：

- 完整 Logo、图形标志和 favicon 三档静态版本。
- 首页关键转场中的 Logo 动效。
- 独立的登录与注册页面，不使用普通全站导航。
- 由折叠纸页、书签和时间戳构成的品牌角色互动。
- 桌面端、移动端和减少动态效果模式的完整降级策略。

本次不修改认证后端协议，不新增第三方动效运行时，也不重构登录和注册之外的产品页面。

## 2. 已确认视觉方向

视觉方向命名为 **Warm Fold · Seam Watchers**。

### 2.1 色彩与排版

- 主背景使用暖纸色和深墨色，形成编辑出版物般的专业质感。
- 赤陶色只用于书签、焦点和少量品牌提示，不作为大面积 CTA 色。
- 表单正文与控件使用 DM Sans；展示标题使用 DM Serif Display。
- 生产实现通过 `next/font` 加载字体，避免运行时外部样式请求和布局偏移。
- 输入框、按钮和表单卡片使用统一但不过度胶囊化的圆角体系。

### 2.2 Logo 系统

Logo 由折叠笔记页和时间播放指针组合成简洁的 N：

- 完整标志：图形标志与 `NoteGen` 字标，用于首页和认证页。
- 图形标志：仅保留折页 N 与播放指针，用于导航栏和紧凑界面。
- favicon：针对 16 至 32 像素重新校正线宽和负空间，不直接缩小完整 SVG。

静态版本采用单色主体和单一指针强调色。动态版本仅在首页和关键转场使用：纸页展开后，播放指针沿时间线滑入并停靠。导航栏、表单输入期间和 favicon 不循环播放动画。

## 3. 认证页布局

登录与注册共用沉浸式双栏 `AuthShell`：

- 左栏：深墨色品牌叙事、Logo、主标题和柔性书签飘带。
- 中缝：两位抽象折纸角色分别位于左右两侧，作为输入状态的辅助反馈。
- 右栏：暖白纸面表单，提供清晰标签、输入、密码显隐、错误和成功反馈。
- 页面不渲染普通 `NavBar`，只保留可返回首页的品牌标志。

注册页沿用相同结构，将表单内容替换为邮箱、显示名称和密码。注册成功状态在表单卡片内完成，不切换到另一套视觉语言。

## 4. 角色设计与状态机

角色不采用真人或动物卡通造型。每个角色都是带折角、纸张压印线、时间戳和书签的抽象纸页雕塑。

`PaperWatchers` 只接受以下显式状态：

| 状态 | 触发条件 | 反馈 |
| --- | --- | --- |
| `idle` | 页面加载或输入失焦 | 静态站在页面中缝两侧 |
| `tracking` | 指针移动或邮箱聚焦 | 眼球在小范围内跟随指针，角色轻微靠近输入区 |
| `private` | 密码框聚焦且密码隐藏 | 下半折页抬起遮眼 |
| `peeking` | 用户显示密码 | 折页留出细缝，视线轻微露出 |
| `error` | 客户端或服务端校验失败 | 两个角色向中间侧看，辅助错误提示 |
| `success` | 登录或注册成功 | 两个角色轻碰并回到静态状态，然后执行跳转或成功展示 |

视线位移限制在约 3 像素内，进入和退出使用 150 至 300 毫秒缓动。错误反馈不使用全屏抖动，成功反馈不使用弹跳或粒子效果。

## 5. 组件结构

建议新增以下边界清晰的组件：

- `BrandMark`：渲染完整标志、图形标志和尺寸变体。
- `AuthShell`：承载双栏布局、品牌文案、表单插槽和响应式结构。
- `PaperWatchers`：根据单一状态枚举渲染角色姿态。
- `BookmarkRibbon`：背景飘带，接收是否允许动态效果的布尔值。
- `PasswordField`：封装真实标签、输入、显隐按钮和可访问名称。
- `usePointerGaze`：将指针位置归一化为受限的视线偏移，不直接操作页面业务状态。
- `useReducedMotionPreference`：统一控制 Logo、角色和飘带的静态降级。

登录和注册页负责认证请求与页面级状态；视觉组件不调用认证 API。现有 `AuthContext`、`apiRegister` 和错误类型保持不变。

## 6. 数据与交互流

1. 页面加载后读取减少动态效果偏好和当前断点。
2. 表单焦点和密码显隐状态映射为 `PaperWatchers` 状态。
3. 用户提交时沿用现有登录或注册 API。
4. 客户端校验失败或 API 返回错误时，显示文本错误并进入 `error` 状态。
5. 登录成功时短暂进入 `success`，随后跳转到原有 `next` 目标。
6. 注册成功时在卡片内显示成功状态，并保留前往登录页的明确操作。

动画状态不得阻塞输入、提交、错误展示或路由跳转。认证结果始终以文本和控件状态为准，角色动作只是冗余反馈。

## 7. 响应式与无障碍

- 桌面端显示两位中缝角色和完整双栏布局。
- 低于平板断点时改为上下布局，中缝角色缩小并位于品牌区和表单区之间。
- 移动端只保留一位角色，关闭鼠标跟随和飘带悬停波动。
- `prefers-reduced-motion: reduce` 下关闭折页、视线、飘带和庆祝动画，保留静态状态差异。
- 所有输入使用真实 `label`；placeholder 不替代标签。
- 密码显隐按钮使用眼睛图标，并提供 `Show password` / `Hide password` 可访问名称。
- 错误容器使用 `role="alert"`，成功或异步进度使用合适的 `aria-live` 状态。
- 键盘焦点清晰可见，视觉顺序与 Tab 顺序一致，触摸目标不小于 44 像素。
- 正文和控件文字满足至少 4.5:1 的对比度。

## 8. 错误处理

- 客户端校验失败：立即显示字段相关文本，不提交请求。
- 未验证账号：保留现有 403 处理和验证引导，不只依赖角色动作。
- 网络或服务异常：显示可重试的通用错误，恢复提交按钮可用状态。
- 重复提交：提交期间禁用按钮并显示加载状态。
- 动画异常或浏览器不支持相关 API：表单仍以静态布局完整工作。

## 9. 测试与验收

### 9.1 自动化测试

- `BrandMark` 三种尺寸输出稳定且具有可访问标题策略。
- 角色状态枚举到 CSS / SVG 姿态的映射正确。
- 密码显隐切换输入类型并更新可访问名称。
- 登录失败、未验证、网络异常和成功跳转保持现有行为。
- 注册密码长度、成功状态和错误恢复保持现有行为。
- 减少动态效果模式不注册指针跟随动画。

### 9.2 浏览器验收

- 在 375、768、1024 和 1440 像素宽度检查布局，无水平滚动。
- 仅用键盘完成登录、注册、密码显隐和错误恢复。
- 检查浅色与深色系统偏好下认证页均保持预设暖纸主题，不发生不可读的主题覆盖。
- 验证邮箱聚焦、密码遮眼、密码偷看、错误侧看和成功轻碰状态。
- 启用减少动态效果后，确认 Logo、角色和飘带全部静态。
- Lighthouse accessibility 目标不低于 90。

## 10. 验收标准

- 登录和注册页不再显示普通全站导航。
- Logo 三档静态资源在导航、小图标和品牌展示场景中清晰可辨。
- 认证角色位于页面中缝，不遮挡标题、输入、错误信息或密码显隐按钮。
- 所有核心认证操作在 JavaScript 动画失败、移动端和减少动态效果模式下仍可完成。
- 不新增 Canvas、Rive 或其他运行时动效依赖；使用现有 React、SVG、CSS 和 Framer Motion 能力实现。
