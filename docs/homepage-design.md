# 首页设计文档：Warm Fold Landing Page

## 1. 设计目标

首页的核心目标不是堆功能，而是让用户在 5 秒内理解产品：

> 这是一个把视频内容转化为结构化学习笔记、章节进度和问答回顾的工具。

首页需要承接 Warm Fold 品牌气质：温暖、轻量、纸张感、学习感、电影化但不过度炫技。整体视觉应像“视频被折叠成一页可回看的笔记”。

本阶段只固化首页设计方案、三屏结构、移动端规则和动效边界，不直接实现业务功能。

---

## 2. 页面范围

首页路径建议为：

```txt
/
```

首页面向未登录用户，主要承担：

1. 说明产品价值。
2. 引导用户登录 / 注册。
3. 展示视频、章节、笔记、问答之间的联动关系。
4. 建立 Warm Fold 的品牌第一印象。

首页不承担复杂操作，不展示真实笔记库，不引入完整工作台交互。

---

## 3. 首页三屏结构

首页采用三屏结构，避免信息过多导致焦点分散。

### 第一屏：Hero / 品牌主张

目标：让用户立刻理解产品是什么，并产生开始使用的动机。

#### 内容结构

左侧为文案与操作区：

```txt
标题：
把视频折叠成可回看的学习笔记

副标题：
上传或导入视频后，系统会自动整理章节、提炼重点，并支持围绕内容继续提问。适合课程、讲座、教程和长视频学习。

主按钮：
开始记录

次按钮：
查看示例
```

右侧为产品预览卡片，不使用完整真实界面，而是做“轻量模拟工作台”：

* 顶部：视频进度条。
* 中部：章节列表。
* 右侧或下方：笔记摘要卡片。
* 底部：问答气泡示例。

视觉上让用户看到：

```txt
视频 → 章节 → 笔记 → 问答
```

这一转换关系。

#### 视觉建议

* 背景使用暖白、浅米色或纸张感渐变。
* 中心区域可以有一条柔性的“书签飘带”贯穿，但不要抢主体。
* 右侧预览卡片使用轻微透视和层叠，像几张折起来的纸。
* Logo 保持单色简洁，不在首页第一屏使用复杂动画。

#### 首屏布局

桌面端：

```txt
左侧文案：45%
右侧产品预览：55%
最大内容宽度：约 1120px - 1200px
首屏高度：至少 760px，允许内容自然撑开
```

移动端：

```txt
文案在上
产品预览在下
按钮纵向排列或主次按钮并排
右侧复杂预览简化为 2-3 张纵向卡片
```

---

### 第二屏：How It Works / 三步流程

目标：解释产品流程，降低用户理解成本。

#### 标题

```txt
从一段视频，到一套可以复习的笔记
```

#### 三个步骤

第一步：导入视频
说明：上传课程、教程、讲座或长视频。

第二步：生成结构
说明：自动拆分章节，提炼重点，形成清晰的学习路径。

第三步：继续提问
说明：围绕视频内容追问、复习、定位原片段。

#### 设计形式

使用三张横向流程卡片：

```txt
[导入视频] → [生成章节与笔记] → [围绕内容问答]
```

每张卡片包含：

* 一个轻量图标。
* 一句短标题。
* 两行以内说明。
* 一条微型状态动画，例如进度线、折页、问答气泡浮现。

不要使用大面积插画，以免和右侧产品预览重复。

#### 交互

* 卡片 hover 时轻微上浮。
* 箭头或连接线可以在滚动进入时依次出现。
* 不做循环播放的大动画。

---

### 第三屏：Use Case + Final CTA / 使用场景与收口

目标：让用户知道什么时候用，并完成最终转化。

#### 标题

```txt
适合所有需要“看完还要记住”的内容
```

#### 场景卡片

建议展示 4 个场景：

1. 在线课程
   用于整理课程章节和知识点。

2. 技术教程
   用于记录操作步骤和关键代码片段。

3. 讲座访谈
   用于提取观点、人物和时间线。

4. 复习备考
   用于把长视频变成可回看的复习材料。

#### 收尾 CTA

底部放一个较大的收尾卡片：

```txt
准备把你的第一个视频变成笔记吗？

主按钮：
开始创建笔记

辅助文字：
无需复杂设置，从一个视频开始。
```

视觉上可以让前面的纸张卡片最终“收束”为一个笔记本封面，呼应 Warm Fold。

---

## 4. 导航与登录入口

首页顶部导航保持轻量，不使用完整工作台导航。

建议结构：

```txt
左侧：Logo + 产品名
中间：功能 / 示例 / 使用场景
右侧：登录 / 开始使用
```

移动端：

* 中间导航隐藏。
* 右侧只保留一个“开始使用”按钮。
* 如需菜单，只使用简单抽屉，不做复杂二级导航。

---

## 5. 移动端规则

移动端优先保证清晰和性能，不强求桌面端的完整视觉效果。

### 布局规则

1. 所有双栏布局改为单栏。
2. 首屏右侧产品预览改为纵向卡片。
3. 三步流程从横向改为纵向。
4. 使用场景卡片从四列改为一列或两列。
5. CTA 按钮触控区域不小于 44px。
6. 不依赖 hover 才能理解内容。

### 字号规则

```txt
Hero 标题：32px - 40px
正文：15px - 17px
卡片标题：16px - 18px
按钮：15px - 16px
```

### 内容取舍

移动端可以隐藏：

* 背景飘带复杂形变。
* 多层纸张透视。
* 多个同时运动的装饰元素。

必须保留：

* 核心标题。
* 主 CTA。
* 视频 → 笔记 → 问答的关系。
* 三步流程。
* 最终 CTA。

## 6. 动效边界

首页动效要服务理解，不做纯炫技。

### 可以使用的动效

1. 页面进入时，Hero 文案轻微上移 + 淡入。
2. 产品预览卡片依次出现。
3. 视频进度条轻微推进一次。
4. 章节高亮与笔记卡片联动一次。
5. Hover 时卡片轻微上浮。
6. 书签飘带可以有极轻微位移。

### 不建议使用的动效

1. 长时间循环的大幅背景动画。
2. 高频闪烁。
3. 滚动过程中强制吸附每一屏。
4. 复杂 3D 翻页。
5. 多个元素同时运动导致视觉噪音。
6. 影响阅读的视差滚动。

### 动效参数建议

```txt
普通过渡：160ms - 240ms
页面进入：360ms - 520ms
缓动：ease-out 或 cubic-bezier(0.22, 1, 0.36, 1)
位移：不超过 16px
缩放：不超过 1.02
```

### 减少动态效果

如果用户系统开启 `prefers-reduced-motion`：

* 关闭飘带动画。
* 关闭进度条自动播放。
* 关闭滚动触发动画。
* 保留基础 hover / focus 状态即可。

## 7. 视觉系统约束

首页必须沿用现有 Warm Fold 方向，不引入新的强视觉风格。

### Logo

* 使用“折叠笔记页 + 播放指针”的方向。
* 静态状态保持清晰。
* 首页导航中不要使用复杂动态 Logo。

### 色彩

建议控制在以下方向：

```txt
背景：暖白、浅米色、淡纸张色
主色：温暖橙棕 / 柔和琥珀色
文字：深灰黑，不用纯黑
辅助色：浅棕、灰米、低饱和蓝灰
警示色：只用于错误或删除，不在首页大量出现
```

### 圆角

```txt
按钮：12px - 14px
普通卡片：18px - 24px
大型产品预览：28px - 32px
```

### 阴影

首页阴影要轻，像纸张浮起，而不是强烈玻璃拟态。

```txt
小卡片：轻微阴影
大卡片：中等扩散阴影
避免纯黑高透明阴影
```

## 8. 组件要求

首页至少需要沉淀以下组件，后续可复用于认证页和工作台：

1. BrandLogo
2. PrimaryButton
3. SecondaryButton
4. LandingSection
5. FeatureCard
6. ProcessStepCard
7. ProductPreviewCard
8. FinalCTA
9. ResponsiveNav

组件要避免只为首页写死，样式应尽量使用统一 token。

---

## 9. 无障碍要求

1. 按钮和链接必须有清晰 focus 状态。
2. 文本与背景对比度必须足够。
3. 动画不能影响内容阅读。
4. 图片或装饰元素需要正确设置 `alt` 或 `aria-hidden`。
5. 键盘可以访问所有 CTA。
6. 移动端触控区域不小于 44px。
7. 首页不能只靠颜色表达状态。

---

## 10. 实现边界与交互跳转

本阶段只固化首页设计方案，不实现首页代码，不修改认证页、笔记本库、笔记工作台或设计系统代码。

### 数据边界

首页中的产品预览、章节列表、笔记摘要和问答气泡均使用静态模拟内容，不接入真实视频、笔记、问答或用户数据接口。

首页不展示真实笔记库，不读取用户历史记录，不引入工作台的完整交互逻辑。

### 登录态规则

首页默认面向未登录用户。

未登录状态下：

* “登录”跳转到 `/login`。
* “开始使用”“开始记录”“开始创建笔记”跳转到登录或注册入口。
* “查看示例”滚动到示例区域，或展示静态示例预览。

已登录状态下：

* 顶部主 CTA 从“开始使用”调整为“进入笔记本库”。
* 点击后跳转到 `/notebooks`。
* 首页仍保持营销页结构，不变成工作台首页。

### 响应式断点

建议按以下断点处理首页布局：

```txt
桌面端：>= 1024px
平板端：768px - 1023px
移动端：< 768px
小屏手机：< 480px
```

桌面端优先展示双栏 Hero 和横向流程卡片。

平板端可以保留双栏结构，但减少装饰元素和卡片层叠。

移动端统一改为单栏布局，隐藏复杂背景动画，保证主标题、CTA、产品关系和三步流程清晰可见。

### 与 P0 的关系

本文档只描述首页需要遵守的视觉方向，不在本阶段落地设计系统 token 或组件代码。

Logo、字体、颜色、圆角、按钮、卡片和基础组件应在 P0 阶段单独处理。首页实现阶段需要复用 P0 沉淀后的设计系统，而不是在首页中重新写一套独立样式。
